Foundations — 01
Governing Colour Principle
One rule across all badge systems: colour tells users whether they can act. Build one mental model — users learn it once and it works everywhere in the app.
Green
Go — available or positively complete
Blue
Act — coordination or action required now
Amber
Wait — in motion, pending, or approaching limit
Red
Stop — blocked, overdue, expired or failed
Teal · Purple
Special — exchange offer, gift, or conditional access
Grey
Neutral — inactive, terminal, or holding
Always pair a badge with a role-specific action prompt. The badge tells users the state; the prompt tells them who acts next. Three amber transaction states look identical — only the prompt disambiguates them.

Accessibility — Contrast & Readability
All 23 text/background combinations pass WCAG AA. The majority hit AAA (7:1+). One constraint to enforce: ink-600 (#956a70) is the lightest text-safe colour — safe on white (4.6:1), borderline on ink-100 (4.2:1, passes only as large text ≥16px bold), and fails on ink-200 or darker. Never use ink-600 for must-read text below 16px bold on any surface darker than white.

Shape Language
4px (sm) = "this is a label." Chips classify, badges state, indicators mark. Colour and icons distinguish roles within this shape. A 六四 chip is red; a 可借閱 badge is green with a checkmark. Same radius, different signals.
10–14px (lg) = "this is a container." Something you browse, scroll, or tap into. The softness invites entry. Cards, strips, and frames all share this feeling.
12px (button) = "this is an action." Considered, editorial, deliberate — not bouncy or playful. Matches the gravity of an app whose subject matter includes 六四 and 國安法.
50% (full) = "look here." A circle is the strongest attractor shape. Reserved for the elements that demand immediate attention: the FAB, the notification pip, the active-state signal.

Layout Spacing vs Component Anatomy
Layout spacing (this scale): space between elements the user perceives as separate — gap between cards, screen-edge padding, title-to-grid. These recur across contexts, risk drift if not centralised, and belong in the global scale.
Component anatomy (not this scale): space inside a single perceived unit — the 2px between a checkmark and its label inside one badge, a chip's vertical padding. These live in one component, are enforced by that component's own definition, and would only clutter the global scale. Sub-4px values (1–3px) are always anatomy, never layout.
The test: a value belongs in the scale when it is (1) layout space between separate elements, (2) recurring across contexts, and (3) at risk of drift if not centralised. It stays local when it is internal construction of one unit, used in one place, already enforced by that component.
Components — 01
Status Chip
Renders a book's ItemStatus — one of five production enum values. Sits top-right of the cover photo overlay on every book card. Built entirely from tokens: --radius-sm (4px), --type-caption (11px), and internal anatomy padding. Each state carries a distinct colour + icon so it reads without relying on text alone.
States — 5 production enum values · bilingual
AVAILABLE 可借用 Available green
EXCHANGEABLE 可交換 Exchangeable blue
GIFT 贈送物 Gift violet
RESERVED 已預留 Reserved amber
TRANSFERRED 已轉讓 Transferred neutral ink
Colour logic: The three "active" states (AVAILABLE, EXCHANGEABLE, GIFT) use distinct functional hues — green, blue, violet — so a user scanning a grid can tell borrow from swap from free at a glance. RESERVED (amber) signals "wait." TRANSFERRED (neutral ink) is deliberately muted — the book is gone, so its chip recedes. Memorial colours are never used for status — status is a mundane UI state, and the memorial palette is reserved for editorial/categorical meaning only.
Bilingual: The chip renders in the active app language via the header toggle. CJK labels come from zh-HK.json, English from en.json — both keyed to the same ItemStatus enum. Colour and icon are identical across languages; only the text swaps. English labels run longer, so the chip is content-width (never fixed-width) to accommodate "Exchangeable" without clipping.

One per card. A book has exactly one status. The chip is singular — never stacked. It always sits top-right of the cover overlay.

Category Chip
Renders a book's category — a free-form string from the category field. Two visual modes: neutral for ordinary categories, memorial-tinted for categories that match a known collective-memory event. The memorial tint is a presentation-layer lookup, not data — the category string itself carries no special flag.
Modes — neutral vs memorial
Neutral — the default for any category string
禁書 政治 散文 紀實 海外
Memorial-tinted — only for categories matching a known event
六四 雨傘 國安法
Why a lookup, not data: Categories are free-form strings (category: String!). The data has no "this is a memorial event" flag. The memorial tint is applied client-side: if the category string matches an entry in a small memorial-events map, render the tinted variant; otherwise render neutral. This keeps the meaning in the design layer where it belongs.
Tags don't translate. A category is content, not UI copy. It has one fixed display form — whatever the curator entered — and renders identically regardless of app language. 六四 stays 六四; "Hong Kong" stays "Hong Kong"; tags can be mixed-script (六四 and "Hong Kong" on the same book). Only the surrounding UI (status chip, buttons, labels) swaps with the language toggle.

Grid flexes to fill columns — width is a fraction of the container, so it grows with the grid's column count across breakpoints. Compact is for the related-books row on the item detail page — small, chip-free, just cover + name for quick recognition. The card radius scales fluidly in all three via --radius-lg.
Composition Rules
Category overflow: Show up to 2 chips. Memorial categories claim slots first (六四 before 散文), so the culturally significant tag always wins limited space. Remaining categories collapse to a +N count in ink-600.
Status is singular, top-right. Exactly one status chip, always over the cover's top-right, backdrop-blurred for legibility on any image.
UI translates, content doesn't: The status chip swaps with app language (可借用 / Available — it's UI copy keyed to the enum). The book name and category tags do not — they're content with one fixed display form each. A tag reads 六四 in both modes; a tag reads "Hong Kong" in both modes. Because English UI labels run longer than CJK, the card never fixes chip width — the frame accommodates content-width chips in either language.
Title clamps to 2 lines. Noto Serif TC, weight 700. Longer names truncate with ellipsis — the full name lives on the detail page.
